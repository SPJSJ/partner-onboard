# Partner Onboard

Admin tool for onboarding Partners and their Representatives, generating a unique
lead-collection form link per Partner, and reviewing leads that come back in.

## Stack

- **Server**: Node.js + Express, deployed as a single Vercel serverless function
  (`api/index.js`).
- **Database**: [libSQL](https://turso.tech) via `@libsql/client`. Locally it defaults to
  a SQLite file at `server/data/partners.db` — no setup needed. In production it talks to
  a hosted Turso database over the network, since Vercel functions have no persistent
  local disk.
- **Client**: React + Vite, built to static files and served from the same Vercel project.

## Local setup

```
npm install
npm run dev
```

This starts the API on `http://localhost:3001` and the web app on `http://localhost:5173`
(the Vite dev server proxies `/api` to the backend). Open `http://localhost:5173` in a
browser. No environment variables are required for local dev — the SQLite file is created
automatically on first run at `server/data/partners.db`.

## Deploying to Vercel

1. **Create a Turso database** (free tier is plenty for this). Easiest via the web
   dashboard at turso.tech: sign up, create a database, and it'll show you a connection
   URL (`libsql://...`) and let you generate an auth token. (If you prefer their CLI,
   see turso.tech/docs for the current install instructions — the commands are
   `turso db create`, `turso db show <name> --url`, and `turso db tokens create <name>`.)

2. **Push this project to a GitHub repo** and import it in Vercel ("Add New… → Project"),
   or deploy straight from the CLI with `npx vercel`. Either way, Vercel will read
   `vercel.json` at the repo root, which builds the client and wires `/api/*` to the
   Express app in `api/index.js`.

3. **Set environment variables** on the Vercel project (Settings → Environment Variables):
   - `TURSO_DATABASE_URL` — from step 1
   - `TURSO_AUTH_TOKEN` — from step 1

4. Deploy. The app and API share one domain, so there's no CORS to configure — the
   partner form links generated by the app (`/form/:token`) will point at your Vercel
   domain automatically.

`server/.env.example` documents the same two variables if you want to test against the
hosted Turso DB locally instead of the local SQLite file — copy it to `server/.env` and
fill it in (`server.js` loads it via `dotenv`).

## What's included

- **Add Partner** (`/partners/new`) — matches the provided mockup: Partner details,
  Contact information, Billing address, one or more Representatives, and a live
  validation panel (Partner ID / Representative ID availability, email/phone/ZIP format,
  duplicate check) backed by real server checks.
- **Partners list** (`/partners`) — searchable by Partner ID or Partner Name.
- **Partner detail** (`/partners/:partnerId`) — full partner record, its
  representatives, the partner's unique lead-form link (copy/open), and every lead
  submitted through that link.
- **Public lead form** (`/form/:token`) — the link generated for each partner. No admin
  layout; Partner ID and Partner Name are pre-filled and read-only. Submissions are
  saved as leads against that partner.

Other sidebar items from the mockup (Dashboard, WPForms Inbox, Representatives, Reports,
Users and Roles, Audit Log) are stubbed as "coming soon" placeholders — out of scope for
this data-entry-focused release.
